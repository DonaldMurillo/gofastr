# Replay suite, 2026-11-14

Claude Code CLI 2.1.325. Three past bugs, each started from the commit
before its fix. Haiku 3 trials, Sonnet 2 trials: 30 cells, $3.76.

| | plain | nudge |
|---|---|---|
| Reported path fixed | 15/15 | 14/15 |
| Other paths with the same defect fixed | 5/30 | 25/30 |

By task, other paths fixed (Haiku, then Sonnet):

| Task | plain | nudge |
|---|---|---|
| `repeated-query-key` (3 paths) | 3/9, 2/6 | 8/9, 6/6 |
| `observer-panic` (1 path) | 0/3, 0/2 | 3/3, 2/2 |
| `undecodable-filter` (2 paths) | 0/6, 0/4 | 4/6, 2/4 |

- **Agents fix what is reported and stop.** Without the nudge they fixed
  the reported path every time and one in six of the other paths. The
  one they did reach was the same function's neighbouring query key.
- **One sentence closed most of the gap.** "Before you finish, check
  whether other code paths have the same defect, and fix those too" took
  the other paths from 5/30 to 25/30, on both models.
- **It costs more.** A nudged Haiku cell used about twice the tool calls
  of a plain one; Sonnet cells cost about the same either way.

The one `nudge` cell marked unfixed (Sonnet, `undecodable-filter`) did
add a warning, but worded it as the audit page's existing callout
instead of "Filter not applied", and said so. The grader matches the
text, so it scored that cell 0.

## With the registry instead of the sentence

A third condition gave the old trees the registry: `primitives for` on a
touched file names the other paths that do the same job. No sentence was
added to the prompt. 30 more cells, $3.11.

| Other paths fixed | plain | registry, first wording | registry, firm wording | nudge |
|---|---|---|---|---|
| Haiku | 3/18 | 3/18 | 5/18 | 15/18 |
| Sonnet | 2/12 | 3/12 | 8/12 | 10/12 |

First wording: "A defect or a change in one of these probably belongs in
all of them. Check each before you finish." Firm wording: "In this
repository a fix to one of these is not finished until every site has
it. Fix them all, or say why a site is exempt."

- **Told by a tool is weaker than told by the person.** With the first
  wording, agents that read the notice fixed the reported path and
  listed the other paths in their summary as "not checked". The firm
  wording moved Sonnet most of the way and Haiku very little.
- **The lookup is skipped about a third of the time.** 11 of 30 registry
  cells never ran `primitives for` or read `primitives/`, on the
  strength of one paragraph in `CLAUDE.md`.
## With the hook

A fourth condition added the registry's hook, which delivers the notice
after the agent changes a twins site, by any tool. 15 cells, $1.73.

| Other paths fixed | plain | registry, firm | hook | nudge |
|---|---|---|---|---|
| Haiku | 3/18 | 5/18 | 6/18 | 15/18 |
| Sonnet | 2/12 | 8/12 | 10/12 | 10/12 |

- **The notice reached every cell**, 15 of 15, against 19 of 30 when the
  agent had to ask.
- **Sonnet acted on it as often as on the sentence.** Haiku mostly did
  not: it fixed the reported path and wrote that the other sites "need
  the same treatment", because the request named one page.
- **No run stayed silent.** Every hook cell either fixed every other
  path (8 of 15) or named the unfixed ones in its summary (7 of 15). With
  the bare report, 13 of 15 summaries did not mention them. The count of
  mentions is a pattern match on the summary, so treat it as rough.

An earlier hook that fired only on the Edit and Write tools reached few
Sonnet cells: Sonnet made most of its edits through the shell. Those 15
cells ($1.58) are not in the table.


## On Opus

trials each: 18 cells, $14.97.

| Other paths fixed | plain | hook | nudge |
|---|---|---|---|
| Opus | 2/12 | 12/12 | 11/12 |

Opus fixed the reported path in all 18 cells. With the bare report it
stopped there, like the smaller models. With the hook it fixed every
other path in every cell.

Three `repeated-query-key` cells and eight others were not graded by the
harness. Two of the three ran past the shared timeout before grading.
The third, and the eight that never started, hit a disk that earlier
workspaces had filled. The three were graded by hand with the same
held-out tests; the eight were rerun.
The harness now grades on its own clock and removes each workspace.

## Registry entries written without knowing the bugs, on Opus

Three more bugs, in the app-spec validator and the UI node contract.
Their registry entries were written by a separate agent that saw the
pre-fix code and the format and was not told the bugs. Plain against
harness, two trials each: 12 cells, $10.23. One harness cell could not
be graded (the harness failed to restore its test files) and is left
out.

| Opus | plain | harness |
|---|---|---|
| Reported path fixed | 6/6 | 5/5 |
| Other paths fixed | 10/20 | 7/15 |
| Updated the docs | 5/6 | 5/5 |
| Added the upgrade note, where the real fix did | 0/4 | 0/3 |

- **Entries written in advance did not name the paths that mattered.**
  The blind entries hold 18 twins, all plausible, and the agents saw
  them. None lists the sibling checks these three fixes needed, and the
  harness cells fixed no more of them than the plain ones.
- **So the earlier result depended on the entries.** Other paths went
  from 2/12 to 12/12 when the entry named them. The registry delivers
  what it holds; it does not find what nobody recorded.
- **The upgrade reminder never arrived.** The stop check shows a part's
  `on_change` lines only when its docs did not change. These agents
  updated the docs unprompted, so the reminder was never shown.

## The stop check asks about sibling paths, on Opus

The stop check was changed to ask, once per session, whether another
code path does the same job, and to show a changed part's `on_change`
lines whether or not its docs changed. Harness condition again on the
same three bugs: 6 cells, $6.19.

| Opus, three bugs with blind entries | plain | harness before | harness after |
|---|---|---|---|
| Other paths fixed | 10/20 | 7/15 | 10/20 |
| Updated the docs | 5/6 | 5/5 | 6/6 |
| Added the upgrade note, where the real fix did | 0/4 | 0/3 | 4/4 |

- **The reminder works.** The upgrade note went from never to every
  time once the `on_change` line reached the agent.
- **The question did not raise the count of other paths fixed.** Every
  run answered it with a list of the paths it checked and why each
  needed nothing. The paths the real fixes also reached were judgment
  calls the agents made differently: one checked the renderer and left
  it because its only caller validates first, where the real fix
  hardened it too.
- So on these bugs "other paths fixed" measures whether the agent drew
  the scope where the maintainer did, which is softer than "missed a
  twin". What changed is that the reasoning is now written down in
  every summary, where a reviewer can disagree with it.

Three tasks, all of the "same defect on a sibling path" kind, two or
three trials a cell. The nudge names that kind of mistake exactly, so
this shows the instruction works for it, not that it generalises.
