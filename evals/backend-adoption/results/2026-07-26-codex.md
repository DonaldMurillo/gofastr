# Codex backend-heavy vertical-slice study — 2026-07-26

## Scope correction

This study does **not** establish which option is the better full-stack web
framework or which people are more likely to adopt. It exercised a
backend-heavy vertical slice: auth, SQLite, owner-scoped CRUD, OpenAPI, MCP,
restart persistence, and one server-rendered dashboard. The dashboard was
checked for required content, not visual quality, accessibility, interaction
quality, responsive behavior, or implementation speed across multiple pages.

The valid narrower result is that Gin was the most reliable and token-efficient
option for this particular contract. GoFastr produced roughly half as much
application source and demonstrated cross-surface schema compression, but its
agents spent much more time and context on framework discovery and visual
verification.

That token comparison is also asymmetric: GoFastr's generated instructions
required browser review, while the neutral Gin and `net/http` instructions did
not. Because this grader barely rewarded UI quality, GoFastr paid for work whose
value was not scored. The measurements describe the observed workflow, but
should not be presented as a general full-stack efficiency ranking.

## Protocol

- Codex CLI `0.145.0`, CLI default model.
- Two independent cold starts each for GoFastr, Gin 1.11.0, and `net/http`.
- A fresh Codex process implemented each app.
- A second fresh process evolved every build with ticket priority and a real
  SQLite migration.
- Deterministic 100-point grading used a built application and real localhost
  HTTP requests.
- Checks covered compile/tests, auth, secure cookies, CSRF/origin rejection,
  owner-scoped REST and MCP, OpenAPI, HTML, password storage, and restart
  persistence.
- Maintenance checks reasserted original OpenAPI and cross-owner mutation
  semantics as well as the new feature.
- UI grading only asserted that the authenticated dashboard rendered ticket
  content. It was not a full-stack design or frontend-product evaluation.

The exact task and grader live one directory above this report. Raw artifacts
are in `dist/backend-adoption/20260726T223611Z/`.

## What actually failed

GoFastr reproduced the same cold-start defect twice: `/openapi.json` returned
200, but the document did not describe the live `/api/tickets` path. The
stricter maintenance regrade reproduced that mismatch in both candidates.
GoFastr run two also lost the original grader-created ticket after repeated
post-migration starts, while run one preserved it.

The second `net/http` candidate validated PATCH input before checking ticket
ownership. A foreign ticket therefore returned 400 for an invalid status
instead of the required 404, leaking resource existence. The stricter
maintenance regrade reproduced the same ordering defect.

Gin had no black-box failures in either run or maintenance pass.

## What the study supports

- GoFastr compressed this backend-heavy application into substantially less
  production code.
- GoFastr's declarative model made the priority change small across persistence,
  REST, MCP, OpenAPI metadata, and HTML.
- The tested GoFastr revision has a reproducible API-prefix/OpenAPI contract
  problem worth fixing independently of any comparative ranking.
- Gin was highly reliable for an explicit backend contract when Codex supplied
  the missing application architecture.
- Hand-built `net/http` code showed more security-semantic variance between
  runs.

## What it does not support

- A conclusion that Gin is the better full-stack framework.
- A conclusion that GoFastr is or is not broadly adoptable.
- A general claim that GoFastr is less AI-efficient. Its visual-review work must
  be evaluated against visual and interaction outcomes before making that claim.
- A comparison of scaffolding quality, multi-page product work, forms,
  validation UX, layouts, components, responsive design, accessibility,
  frontend state, assets, or deployment.

## Limitations

- Two repetitions expose variance but are not statistically sufficient.
- Gin's first run encountered a missing transitive module cache entry; it
  recovered in the same session after the cache was warmed. Its perfect score
  and slower of the two Gin times were retained.
- `net/http` is a control, not a feature-equivalent framework.
- Gin is a router-first framework, not a feature-equivalent full-stack
  framework; Codex authored the layers Gin does not provide.
- GoFastr alone instructed its agent to perform extensive browser review, while
  the grader did not meaningfully score the resulting UI quality.
- Hosted frameworks were excluded because their runtime/control-plane
  requirements would make this local benchmark incomparable.
- No subjective UI-quality judge was used.
