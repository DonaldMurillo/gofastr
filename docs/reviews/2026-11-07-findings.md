## Counting rules

- Count only a documented or otherwise established supported behavior that
  reproducibly differs from the observed result.
- Execute a fresh reproduction independently of the review worker, preferably
  through a public API or the actual HTTP handler, and retain the reproducer.
- Count one root cause once, even when several spellings, endpoints, or
  symptoms expose it. Label conditional compatibility issues explicitly.
- Do not count speculative findings, unsupported scenarios, duplicate
  reports, stale documentation alone, or undecided contracts.
- A passing existing suite is evidence about that suite, not proof that
  the reviewed package has no bugs. Never manufacture findings to meet the target.
