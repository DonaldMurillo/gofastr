# Internationalization

`core/i18n` is GoFastr's small i18n primitive: locale negotiation from
`Accept-Language`, JSON-backed message catalogs with `{{placeholder}}`
interpolation, CLDR plural categories for every language, and CLDR
number, date, currency and list formatting.

The goal is to make "translate this string for this caller's locale"
trivial without pulling in the full ICU stack. The plural rules and the
number, date and list patterns come from a CLDR 47 table generated into
the package (`cldr_tables.gen.go`), because `golang.org/x/text`'s data is
older: its plural rules are CLDR 32's, where a French million is
`other` and not `many`.

## Wiring

```go
import "github.com/DonaldMurillo/gofastr/core/i18n"

// Load translations from disk (an embed.FS works the same way).
cat, err := i18n.LoadJSONCatalog(os.DirFS("locales"), ".")
if err != nil { /* ... */ }

tr := i18n.NewTranslator(cat, "en") // "en" = fallback locale

app := framework.NewApp(framework.WithI18n(tr))
```

`framework.WithI18n` does four things:

1. Records the Translator on the App.
2. Wires `i18n.Middleware(tr)` into the default chain so every request
   gets a `Locale` in `r.Context()` from `Accept-Language` (or the
   `X-Locale` override header, or a locale resolver, described below).
3. **Bridges the translator into `r.Context()` for `framework/ui`.** A
   second middleware stashes the Translator via
   `i18nui.WithTranslator`, so every `framework/ui` component that
   reads `r.Context()` resolves its labels through the catalog
   automatically. No manual `WithTranslator` call is needed.
4. Installs the Translator as `i18n.Default()` so the package-level
   `i18n.T(ctx, key, params...)` helper works from anywhere.

Pair with `WithoutDefaultMiddleware` and the framework panics. Mount
`i18n.Middleware(tr)` (plus the translator bridge) explicitly in your
custom chain instead.

## Catalog format

Files are named `<locale>.json` (e.g. `en.json`, `fr.json`,
`fr-CA.json`). Keys nest freely; nested objects are flattened with
`.` separators *unless* every key is a CLDR plural category, in which
case the bucket becomes a plural message.

```json
{
  "welcome": "Hello, {{name}}!",
  "cart": {
    "empty": "Your cart is empty",
    "items": {
      "one": "1 item in cart",
      "other": "{{count}} items in cart"
    }
  }
}
```

After loading:

| Key             | Form    |
|-----------------|---------|
| `welcome`       | Text    |
| `cart.empty`    | Text    |
| `cart.items`    | Plural (`one` / `other`) |

Plural categories recognised: `zero`, `one`, `two`, `few`, `many`,
`other`. Catalogs may also be built in code via
`i18n.NewMapCatalog()` for tests or embedded strings.

## Using a translation

```go
ctx := r.Context()                     // locale already attached by middleware
name := "Alice"
msg := app.T(ctx, "welcome", map[string]any{"name": name})
// "Hello, Alice!" in en, "Bonjour, Alice !" in fr, ...
```

Or via the package-level helper:

```go
msg := i18n.T(ctx, "welcome", map[string]any{"name": name})
```

Both consult the same Translator.

### Placeholders

`{{name}}` is replaced with the matching params value. A number (any
integer or float kind) is written the reader's way, `1,234` in English
and `1 234` in French, so pass the int, not `strconv.Itoa(n)`; anything
else is stringified by `fmt`. Unknown placeholders are **left intact**,
which is easier to spot during development than silently empty.

### Plurals

Pass a numeric `count` (or `n`) in params; the Translator picks the
category for the request locale and interpolates.

<!-- gofastr:compile
import "github.com/DonaldMurillo/gofastr/core/i18n"
import "context"
var ctx = context.Background()
-->
```go
i18n.T(ctx, "cart.items", map[string]any{"count": 3})
// "3 items in cart" (en, "other")
```

Every language's rule is CLDR 47's: Russian's 21 is `one` and 25 is
`many`, Arabic uses all six forms, French's 1.5 is `one` and its
1,000,000 is `many`. A regional locale takes its parent's rule
(`pt-AO` reads as `pt-PT`), and a language CLDR has no rule for reads
as English. A count is an integer, a finite float, or a decimal
string, and the string's written zeros count: English's `"1.0"` is
`other`. A form the message leaves out falls back to `other`.

## Locale negotiation

By default the middleware uses `Accept-Language` and picks the highest
q-value entry that matches a locale in the catalog (with progressive
language-base fallback: `fr-CA` → `fr`). When nothing matches, the
Translator's fallback locale wins.

A request header `X-Locale: ja` short-circuits negotiation, useful
for tests, A/B switches, and apps that prefer locale routing via path
or query.

You can also call `i18n.Negotiate(tr, r)` directly when wiring custom
middleware (e.g. when you need to write the locale to a cookie).

### Per-user locale (cookie) switching

`Middleware` and `Negotiate` accept optional resolvers that run
**before** the headers, so a stored per-user locale can win over the
browser's `Accept-Language`. Resolution order is: locale resolver(s) →
`X-Locale` → `Accept-Language` → fallback.

A resolver value only wins when it matches a catalog locale (with the
same `fr-CA` → `fr` fallback the headers use); an unknown, malformed,
or over-long value falls through to the next source. Resolver values
are attacker-controlled (cookies), so they are length- and
character-bounded before matching.

Use `i18n.CookieLocale(name)` for the common cookie case, and wire it
through `framework.WithLocaleResolver` on the App:

```go
app := framework.NewApp(
    framework.WithI18n(tr),
    framework.WithLocaleResolver(i18n.CookieLocale("locale")),
)
```

A "change language" handler sets the cookie and redirects back. The
cookie carries `HttpOnly`, `Secure` and `SameSite Strict` (a locale
preference never needs script access or cross-site rides), and the
Referer is resolved to a same-origin relative path first: the header is
attacker-controlled, so a bare `r.Referer()` redirect would send the
user (and the fresh cookie) to whatever page linked here.

<!-- gofastr:compile
import "github.com/DonaldMurillo/gofastr/framework"
var app = framework.NewApp()
import "net/http"
import "net/url"
import "strings"
-->
```go
func setLocale(w http.ResponseWriter, r *http.Request) {
    lang := r.FormValue("lang") // validate against your catalog
    http.SetCookie(w, &http.Cookie{
        Name:     "locale",
        Value:    lang,
        Path:     "/",
        HttpOnly: true,
        Secure:   true,
        SameSite: http.SameSiteStrictMode,
    })
    http.Redirect(w, r, backToSender(r), http.StatusSeeOther)
}

// backToSender turns the Referer into a same-origin relative path, "/"
// when it is anything else (missing, absolute on another host, or a
// protocol-relative URL). The Referer header is attacker-controlled;
// redirecting to it raw is an open redirect.
func backToSender(r *http.Request) string {
    u, err := url.Parse(r.Referer())
    if err != nil || u.Host != "" && !strings.EqualFold(u.Host, r.Host) {
        return "/"
    }
    if p := u.Path; strings.HasPrefix(p, "/") && !strings.HasPrefix(p, "//") {
        return p
    }
    return "/"
}
```

`WithLocaleResolver` panics if used without `WithI18n`. Locale
resolution is meaningless without a translator to resolve against.

## Formatting numbers, dates and lists

Every formatter takes the request's context and writes in its locale. A
locale CLDR does not cover, or a context with none, writes English.

<!-- gofastr:compile
import "context"
import "time"
import "github.com/DonaldMurillo/gofastr/core/i18n"
var ctx = context.Background()
var t time.Time
-->
```go
i18n.Number(ctx, 1234.5)                          // "1,234.5"   fr: "1 234,5"
i18n.Number(ctx, 2.0, i18n.MinFraction(2))        // "2.00"
i18n.Percent(ctx, 0.25)                           // "25%"       fr: "25 %"
i18n.Currency(ctx, 1234.5, "EUR")                 // "€1,234.50" fr: "1 234,50 €"
i18n.Date(ctx, t, i18n.DateMedium)                // "Mar 5, 2026"
i18n.DateTime(ctx, t, i18n.DateMedium, i18n.TimeShort) // "Mar 5, 2026, 2:05 PM"
i18n.List(ctx, []string{"a", "b", "c"})           // "a, b, and c" fr: "a, b et c"
i18n.ListOr(ctx, []string{"a", "b"})              // "a or b"
```

- **Digits and grouping are the locale's.** Egyptian Arabic writes
  `١٢٣`, Indian English groups `12,34,567`.
- **Floats round** to three fraction digits, `Percent` to whole percents
  and `Currency` to the currency's own digits (none for JPY), unless
  `MinFraction` / `MaxFraction` say otherwise. NaN and the infinities
  print as the locale's symbols.
- **`i18n.Decimal(ctx, s, opts...)`** takes a plain decimal string
  (`"-1234.5"`, what a NUMERIC column or `big.Rat.FloatString` hands
  back) and never routes it through a float64, so a value past 15–17
  significant digits prints exactly. It rounds half away from zero and
  returns `ok == false` for anything that is not a sign, digits and a
  fraction: exponents, fractions like `"1/3"`, and strings over 512
  bytes.
- **Dates use `t`'s own zone.** Convert with `t.In(loc)` first to show
  another zone's date. `DateYearMonth`, `DateMonthDay` and
  `DateWeekdayMonthDay` are CLDR's skeletons for partial dates.
- **`i18n.FillContext(ctx, s, params)`** is `i18n.Fill` with numbers
  written the reader's way: what a phrase does, for a template that
  arrives as a plain string.
- **`i18n.Dir(tag)`** is `"rtl"` or `"ltr"` from the language's script,
  its own subtag or CLDR's likely one (`ar`, `he`, `fa`, `ur`, `dv`,
  `az-Arab`). The app writes it on `<html dir>` (see "The document
  language").

The `rawtext` analyzer's `numtext` arm keeps Go's own digits out of the
page: a `strconv.Itoa`, `FormatInt`/`FormatFloat` or `fmt.Sprint(f)` of a number that
reaches a phrase param, `render.Text`, a label attribute or a UI field
is reported, directly or through a local variable that holds it. Pass
the number itself, or format it with `i18n.Number`.

## What's NOT in this package

- **ICU message format, compact numbers (`1.2K`), units and relative
  time.** Write those as phrases with a count, the way
  `framework/ui.Ago` does.
- **CLDR time zone names.** `i18n.Time` writes Go's zone abbreviation
  in English and the locale's GMT format elsewhere (`UTC+1` in French).
- **Locale routing via path prefix (`/en/...`, `/fr/...`).** Roll your
  own router prefix handling and set `X-Locale` on the inner request,
  or call `i18n.WithContext(ctx, locale)` before `next.ServeHTTP`.

## Translating framework/ui component labels

Every word a `framework/ui` component says is an `i18n.Phrase` in
`framework/i18nui` (`i18nui.PaginationNext`, `i18nui.TableSortedBy`,
`i18nui.KeyCtrl`, ...). A component says a phrase with
`phrase.Text(ctx)`, so the reader's locale picks the words. Once
`WithI18n` is set, the bridge middleware puts the translator on
`r.Context()`, and a component handed that context needs no other
wiring.

Placeholders are `{{name}}` everywhere: in phrases, in catalogs, in
`headless.Strings` fields and in the runtime's strings. `i18n.Fill(s,
params)` fills a template that arrives as a plain string. It writes each
value as given and never rescans it, and it leaves an unknown placeholder
as written. `i18nui.HTML(ctx, phrase, vars)` is the same for a line that
carries markup, such as a bold name or a link: the translated text is
escaped, and each `{{name}}` becomes `vars[name]`, which the caller
built from escaped parts.

### The `Ctx` field pattern

Components that take a config struct expose a `Ctx context.Context`
field. Pass the request context and the component says its words in the
reader's language. Pass nothing and it uses `context.Background()`,
which says English. An explicit label field on the config
(`SubmitLabel`, `Placeholder`, `CTALabel`, ...) always wins over the
phrase.

```go
h := ui.DataTable(ui.DataTableConfig{
    Columns: cols,
    Rows:    rows,
    Ctx:     r.Context(), // locale + translator from the bridge
})
```

### Mounted widgets

A widget you mount once at startup has no reader when you build it. Its
body renders on every request that shows or opens it, so the framework's
own words in it follow that request's locale: the confirm dialog's
Confirm and Cancel, the lightbox's Prev, Next and Download, the
notification bell's empty text, the shortcut sheet's title and close
button, and the command palette's placeholder and key hints.
`LightboxConfig` and `ConfirmActionConfig` have no `Ctx` field for that
reason.

Words you pass in are said as given. When the rows or commands should be
translated too, mount the `Func` variant, which builds the config for
each request:

```go
func paletteConfig(ctx context.Context) ui.CommandPaletteConfig {
    return ui.CommandPaletteConfig{
        FallbackHref: "/search",
        Commands:     []ui.PaletteCommand{{Label: homePhrase.Text(ctx), Href: "/"}},
        Ctx:          ctx,
    }
}

// At startup:
widget.MountBuilder(app.Router(), ui.CommandPaletteFunc(paletteConfig))
// In the page chrome, the trigger for this request:
trigger, _ := ui.CommandPalette(paletteConfig(r.Context()))
```

`ui.ShortcutSheetFunc` is the same for the shortcut sheet. The widget's
name, shortcut and fallback link come from `build(context.Background())`.

### The `ui.*` key namespace

Component phrases live under `ui.*` (`ui.pagination.next`,
`ui.table.sortedBy`, `ui.key.ctrl`). Your catalog can override any of
them: add the key to a locale's JSON and it wins for that locale. A key
you leave out keeps its English, so a catalog with no `ui.*` entries
renders the English page.

Keycap words are phrases too. `ui.ShortcutHint` prints `Ctrl`, `Esc`,
`Tab` and `Space` from `ui.key.*`, because a German keyboard says
`Strg` where an English one says `Ctrl`.

### Per-entity keys (`entity.*`, `nav.groups.*`)

Entity screens resolve their labels through the `i18nui` entity helpers.
These keys are built per entity. They name the app's own entities,
fields, views, form sections and nav groups, so no phrase defines them.
The fallback chain is: the catalog entry, then the value the entity's
`Display` config declares (see
[Entity declarations](entity-declarations.md)), then the key title-cased
(`past_due` becomes `Past due`). A nested JSON catalog holds them all,
since every key path ends in a string:

| Key | Helper | Fallback when nothing is set |
| --- | --- | --- |
| `entity.<entity>.singular` / `.plural` | `EntitySingular` / `EntityPlural` | entity name singularized + title-cased / entity name title-cased |
| `entity.<entity>.description` | `EntityDescription` | empty (prose has no derived text) |
| `entity.<entity>.fields.<field>.label` | `FieldLabel`, `RelationLabel` | the Display label, else the humanized field name; `RelationLabel` (a Relation field) drops a trailing `_id`, so `customer_id` reads "Customer" |
| `entity.<entity>.fields.<field>.help` | `FieldHelp` | the Display help, else empty |
| `entity.<entity>.fields.<field>.values.<value>` | `FieldValueLabel` | the value title-cased |
| `entity.<entity>.views.<key>` | `ViewLabel` | the view's label, else the key title-cased |
| `entity.<entity>.transitions.<key>` | `TransitionLabel` | the move's label, else the key title-cased |
| `entity.<entity>.sections.<key>` | `SectionLabel` | the key title-cased |
| `nav.groups.<key>` | `NavGroupLabel` | the key title-cased |

Every helper also consults a translator left on the context by the
`WithI18n` bridge when its `tr` argument is nil.

### Pseudo-locale testing

`i18nui.Pseudo(s)` pseudo-localizes a string: every letter accented,
every vowel doubled, the whole bracketed and padded until it is at
least a third longer (about what German or Spanish adds to English).
`{{placeholders}}` stay as written. `i18nui.AddPseudo(catalog, "en-XA")`
puts the pseudo form of every defined phrase into a `*i18n.MapCatalog`
under a tag, so a page browsed with `Accept-Language: en-XA` shows any
text that skipped the catalog as plain English and any layout that
cannot take longer words as overflow.

```go
cat, _ := i18n.LoadJSONCatalog(locales, "locales")
if os.Getenv("PSEUDO_LOCALE") == "1" {
	i18nui.AddPseudo(cat, "en-XA")
}
app := framework.NewApp(framework.WithI18n(i18n.NewTranslator(cat, "en")))
```

Meridian turns it on with `MERIDIAN_PSEUDO_LOCALE=1`, and its
`TestE2E_AdminPseudoLocaleOverflow` browses every admin screen in it,
and in Spanish, at desktop and phone widths. It fails on a page that
scrolls sideways, content past the screen, a control that leaves or is
covered inside its box, or text clipped with no ellipsis.

### Headless components: `ui.StringsFor`

Headless components (`framework/headless`) take their words through a
typed `headless.Strings` prop rather than per-config label fields, so
the whole table resolves in one call:

```go
headless.SystemBanner(headless.SystemBannerProps{
	ID: "sys-maint", Tone: "danger", Title: "Ending in 4 minutes",
	Strings: ui.StringsFor(r.Context()), // every field from the catalog
}, nil)
```

Each field maps to one `i18nui` phrase. With no translator on the ctx,
and for any key the catalog misses, the field keeps the English
`headless` ships, so a partial catalog is safe. Fields with a value to
put in (`Dismiss: {{title}}`, `{{n}} files selected: {{names}}.`) travel
unfilled, and headless or the runtime fills them. A translation may move
a placeholder but must keep the set. One that names a different set is
refused and the field stays English, because the alternative is a
literal `{{n}}` or a lost count inside an accessible name, where nobody
sighted would see it.

`ui.StringsFor` also hands the request to the table
(`Strings.ForRequest`), so the numbers headless writes, a step number, a
count or a slider value, follow the reader's locale through
`Strings.Number`. A counter or meter the browser updates carries
`data-cui-signal-mode="number"`, which loads the `headless-numbers`
runtime module: it rewrites each new value with `Intl.NumberFormat` for
the page's `<html lang>`, so the live number matches the server's.

### Checking a catalog: `i18n.CheckCatalog`

A refused or missing translation is invisible on its own: the page says
one English sentence among the translated ones. `i18n.CheckCatalog`
compares a locale's catalog with every phrase the program defines and
reports three problems:

- **unknown key**: an entry no `Define` registered, left behind by a
  rename or hidden by a typo.
- **placeholders differ**: a translation that names a `{{placeholder}}`
  its English does not fill, or drops one it does.
- **missing**: a phrase under a `Require`d prefix that the locale does
  not translate.

Only phrases linked into the binary are known, so call it from a test
in the package that wires the whole app, once per locale you ship:

```go
func TestSpanishCatalog(t *testing.T) {
	cat, err := i18n.LoadJSONCatalog(locales, "locales")
	if err != nil {
		t.Fatal(err)
	}
	for _, is := range i18n.CheckCatalog(cat, "es",
		i18n.Skip("entity.", "nav."), // the app's data, not phrases
		i18n.Require("ui.")) {        // every component word translated
		t.Errorf("%s: %s (English %q, Spanish %q)", is.Key, is.Problem, is.English, is.Text)
	}
}
```

### Words the browser says: the runtime strings block

The runtime says a few things itself: a failed request's toast, a
navigation that could not load, the embed frame's error, a local
entity's validation messages. Those are phrases too, registered with
`runtime.RegisterStrings(phrases...)` from the package that owns them.
On every page the host writes the ones the reader's locale translates
into a `<script type="application/json" id="gofastr-strings">` block,
and the runtime's `say(key, english, params)` reads it, falling back to
the English argument on a miss. An English reader's page carries no
block at all.

A test walks the repo's JavaScript and holds every `say('key',
'English'` call to a registered phrase with the same English, and every
registered phrase to a call. Change the words in one place and the test
names the other. `core-ui/check.LintRuntimeProse` refuses literal prose
written straight into a toast, a `textContent`, an `aria-label` or a
`title` in runtime JavaScript.

A client-side navigation keeps the document, and with it the first
page's block. So the destination carries its own: a partial response's
page-head template has a `data-cui-strings` attribute, a full fetch has
its `#gofastr-strings` block, and the runtime swaps `say()`'s table on
each navigation. A destination with neither is English, which clears a
Spanish page's table when the reader moves to an English one.

## Beyond the page body

### Screen titles and descriptions

`ScreenTitle` and `ScreenDescription` take the request's context, so a
page's tab title and its description meta speak the reader's language:

```go
var helpTitle = i18n.Define("help.title", "Help center")

func (s *HelpScreen) ScreenTitle(ctx context.Context) string { return helpTitle.Text(ctx) }
```

`App.Register` also reads each once with a bare context, for the route
table and a route's default title. With no locale on it, that copy is
the phrase's English. The `rawtext` analyzer refuses a literal returned
from either method in framework code. A component that still declares
the old `ScreenTitle() string` or `ScreenDescription() string` makes
`Register` and `WithNotFoundBody` panic, because that method satisfies
neither interface.

### Requests the router never sees

`App.Start` negotiates the locale ahead of the server wrappers and the
setup wizard, which run before the router and its i18n middleware. A
battery page that renders outside the app shell (the sign-in gate, the
setup wizard, the magic-link confirmation page) writes
`<html lang>` with `i18n.DocLang(ctx)`: the negotiated locale when the
catalog has it, the translator's fallback when it does not, and `en`
with no translator.

### Mail

An email is read later, but it is written for the person who asked.
`BodyTemplate` on the password-reset, email-verification and magic-link
configs takes a context carrying the requester's locale, so a phrase
rendered in it reads in their language:

```go
var resetBody = i18n.Define("mail.reset_body", "Reset your password: {{url}}")

auth.PasswordResetConfig{
    BodyTemplate: func(ctx context.Context, url string) string {
        return resetBody.Text(ctx, map[string]any{"url": url})
    },
}
```

A notification is written for its recipient, not for the request that
sent it. Set `notify.Recipient.Locale` to the recipient's stored
preference and `Send` renders the message under it. A tag the catalog
lacks falls back to the catalog's fallback, not to the sender's
language; an empty tag keeps the caller's locale. See `gofastr docs notifications`
→ "Translated notifications".

### A user's stored language

Storing a language per user is the app's job: `auth.User` has no locale
field. Keep it on your own user table, and when the user signs in or
changes it, set the cookie `i18n.CookieLocale` reads (see "Per-user
locale (cookie) switching" above). The resolver also runs before the
router, for the setup wizard and server wrappers, where no session has
been read yet. A cookie reaches it there; a session lookup would not.

### Text with no request

A desktop shell's menus and About box, and a page a CLI writes for the
browser, have no `Accept-Language` to read. `i18n.Match(tr, tags...)`
picks the first of a preference list the catalog has, the way
negotiation reads the header, and `i18n.EnvLocale(tr)` reads the
process environment (`LANGUAGE`, then `LC_ALL`, `LC_MESSAGES`, `LANG`).
`desktop.ShellContext` combines them: the OS's preferred languages
first, then the environment. The settings window's title and
`OnSettings` follow that locale.

## Framework messages and error codes

Every message the framework can send a person is an `i18n.Phrase`: a
catalog key plus the English used when no catalog has the key. Error
bodies, validation messages, plain-text refusals and battery screens
all read them, so one catalog translates the lot.

```go
var vatInvalid = i18n.Define("validation.vat_invalid", "is not a valid VAT number")

vatInvalid.Key()                // "validation.vat_invalid"
vatInvalid.Code()               // "vat_invalid": the key's last segment
vatInvalid.Text(r.Context())    // the request's locale, English on a miss
vatInvalid.Format(nil)          // always English (logs, Error() methods)
```

`Define` runs at package level, with a constant key and constant
English. It panics on a malformed key, and on a key another package
already defined with different English. `i18n.Phrases()` lists every
defined phrase, which is what a catalog-completeness test reads.
Placeholders use the catalog's `{{name}}` form.

### The error contract

A JSON error body carries the text in the request's locale and the
phrase's code beside it. A client branches on `reason`, never on
`error` or `message`:

```json
{"error": "ya está en uso", "code": 409, "reason": "unique_taken"}
```

The field is `reason` because `code` already holds the HTTP status.
Field-level failures add `field_reasons`, one code per message in
`fields`, in the same order:

```json
{
  "code": 400, "reason": "validation_failed", "message": "validation failed",
  "fields": {"email": ["is required"]},
  "field_reasons": {"email": ["required"]}
}
```

Every envelope the framework writes follows this: `core/handler`
errors, `framework/crud` (single, batch and state-move results),
`battery/auth` JSON bodies, entity bulk actions and saved views,
desktop preferences, semantic search. The OpenAPI document lists
`reason` and `field_reasons` on its error schemas, and the generated Go
client, JS SDK and CLI decode them. Auth's form-redirect `?error=` codes
are the same codes (`invalid_credentials`, `rate_limit`, ...).

The pieces, all in `core/i18n` unless named:

| Piece | What it does |
| --- | --- |
| `i18n.Error{Reason, Params, Err}`, `i18n.NewError(p, params)` | An error that names its phrase. `Error()` is the English; `Err` is a wrapped cause, never shown |
| `i18n.Wrap(p, err, params)` | An `*i18n.Error` for `p` with `err` as its `{{detail}}` and its cause. A `Phrased` cause translates inside the frame: `nested filter "author.age_like": operator "like" cannot filter "age" (type int)` |
| `i18n.Phrased` | The interface such errors implement. Writers find one anywhere in an error's chain |
| `i18n.ErrorText(ctx, err, frame)` | Text and code for any error. The text is the outermost `Phrased` error, causes included; the code is the innermost one's (`op_type_mismatch` above), the most specific. With no `Phrased` error, err's text fills `frame`'s `{{detail}}` |
| `i18n.HTTPError(w, r, status, p, params)` | `http.Error` with the text translated |
| `i18n.HTTPErrorFor(w, r, status, err)` | The same for an error: a `Phrased` error translates, any other writes the status phrase, so a driver's or library's text never reaches the body |
| `i18n.StatusPhrase(status)` | The generic phrase per status (`error.internal`, "internal server error") |
| `handler.Fail(code, p, params)` | A `*handler.Error` from a phrase |
| `handler.WrapError(code, p, err)` | The same, keeping `err` as the cause |
| `handler.ValidationError(map[string][]schema.Violation)` | A 400 with `fields` and `field_reasons` |
| `handler.WriteError(w, r, err)` | Writes any error as the envelope above in `r`'s locale |
| `schema.Violation{Reason, Params}` | One field failure. Built-in validators return them; `schema.Reason*` are their phrases (`validation.required`, `validation.max_length`, `validation.unique_taken`, ...) |

`handler.Errorf` is still there for an app's own wording, sent as
written with no code. Framework code never uses it.

An app's validators define phrases the same way, and their messages
translate with no extra wiring:

```go
var vatInvalid = i18n.Define("validation.vat_invalid", "is not a valid VAT number")

func checkVAT(v any) error {
	if !validVAT(v) {
		return schema.Violation{Reason: vatInvalid}
	}
	return nil
}
```

The `framework/entity` validators (`Required`, `Unique`) write the
`validation.required` and `validation.unique_taken` phrases in the
context's locale.

### Translating them

The catalog key is the phrase's key, so a locale file translates a
framework message by naming it:

```json
{
  "validation": {
    "required": "es obligatorio",
    "max_length": "debe tener como máximo {{max}} caracteres",
    "unique_taken": "ya está en uso"
  },
  "error": {
    "not_found": "no encontrado"
  }
}
```

Namespaces: `error.*` for request-level refusals, `validation.*` for
field failures, and one namespace per battery or package for its own
messages (`auth.*`, `desktop.*`, `entityui.*`, `semantic.*`, ...).
Query parsers have theirs too: `filter.*` (`?field_<op>=`, `?sort=`,
`?where=`), `dsl.*` (the query DSL, `?filter=` expressions) and
`pagination.*` (cursors). A crud list answers a bad query with the
parser's code, `unknown_filter` rather than a generic one. An
untranslated key falls back to its English.

### The rawtext analyzer

`make analyze` runs `rawtext` over the module's `core/`, `framework/`,
`battery/` and `core-ui/` packages. It refuses the shapes that send
English past the catalog:

- a bare `http.Error` (use `i18n.HTTPError`);
- `i18n.Define` inside a function body, or with a computed key or
  English;
- `handler.Errorf`, or a `handler.Error` literal that sets `Message`;
- a response helper taking an `http.ResponseWriter` and a string
  parameter named `msg`, `message`, `errMsg` or the like;
- a map literal whose `"error"` or `"message"` entry is English prose
  or an error's `.Error()` text;
- a constant JSON body written straight to the response
  (`fmt.Fprintf(w, ...)`, `io.WriteString`, `w.Write([]byte(...))`)
  whose `"error"`, `"message"`, `"title"` or `"detail"` is prose;
- words written into the page: a constant passed to `render.Text`, set
  as an `aria-label`, `title`, `placeholder` or `alt`, or set on a UI
  component's `Label`/`Title`/`Text`-style field, plus the same constant
  passed to a package helper whose parameter reaches one of those
  (`chartEmpty(ctx, ..., "No data yet", ...)`), a local variable or
  parameter that holds such a constant (`aria := "Page steps"` written
  later), and an index write into an attribute map
  (`attrs["aria-label"] = "Close"`);
- a number in Go's digits (`strconv.Itoa`, `fmt.Sprint`) at any of
  those sinks or in a phrase's params, including one held in a local
  first (`n := strconv.Itoa(size)` passed as `{"n": n}`);
- a `ScreenTitle` or `ScreenDescription` method returning a constant.

A site that sends text as written on purpose (an agent protocol's
documented English detail, for one) carries
`//gofastr:allow(rawtext) <why>`. Apps and examples are outside its
scope.

### Still English

- **OpenAPI descriptions, `llm.md`, `llms.txt` and the Markdown
  404.** They are written for developers and agents, and stay English.
- **Agent protocols.** MCP and A2A JSON-RPC error messages, A2A task
  text, Web Bot Auth problem details and the desktop bridge's
  `{"code", "message"}` answers are protocol text for a program, beside
  their own codes. The raw-body sites carry the allow marker.

## The document language

`<html lang>` is a separate thing from the message catalog, and it is the one
piece of i18n a site cannot skip. It is what a screen reader reads to pick
pronunciation rules (WCAG 3.1.1, Language of Page), and what a full-text
indexer such as Pagefind reads to decide which language index a page belongs to
and which stemmer to apply.

`WithLang` sets one language for the whole app. That is right until the app
serves two, at which point every translated page claims the site language: the
Spanish pages are read aloud with English rules and filed in the English index.

### Per route

Most multilingual sites put a language on a path prefix, so a route rule is all
they need:

```go
application := app.NewApp("docs").
    WithLang("en").
    WithLangFunc(func(path string) string {
        if strings.HasPrefix(path, "/es/") {
            return "es"
        }
        return "" // fall back to Lang
    })
```

`LangFunc` is called with the page path on every full-page render. Returning
`""` falls back to the request's negotiated locale (`i18n.FromContext(ctx)`,
set by `WithI18n`'s middleware), then to `Lang`. `App.LangFor(ctx, path)`
exposes the same answer to callers that build their own document shells.

With `WithI18n` and no `LangFunc`, a French reader's page is therefore
`<html lang="fr">`: the document says the language the catalog spoke.

### Per page

A page that knows its own language declares it, which covers a route whose
language is data rather than path:

```go
func (s *ArticleScreen) ScreenLang() string { return s.article.Lang }
```

`ScreenLanger` is read **after** `Load`, exactly like `ScreenTitle`, so a
dynamic route can take the tag from the content it fetched. It beats
`App.LangFunc` for that page. Returning `""` falls through to `LangFunc`, then
the negotiated locale, then `Lang`, then `"en"`.

### Direction

The page's direction follows its language. Every full page carries
`<html dir>` from `i18n.Dir(lang)`, so an Arabic, Hebrew or Persian page
is `dir="rtl"` with nothing to set. After a client navigation the core
runtime copies only the language; the `doc-dir` runtime module, which
the first `data-cui-dir="rtl"` marker loads, copies the direction. A
site that never serves a right-to-left language never fetches it.

The kit mirrors with it. Its CSS uses logical properties
(`inset-inline-start`, `padding-inline-end`, `border-inline-end`,
`text-align: start`), so the sidebar, list indents, chips, the select
chevron, switches and toggles, the segmented indicator and the timeline
rail all flip. Positions named by a side mean the reading direction's
start or end: a `bottom-right` notification, back-to-top button or
widget, and an `Edge` drawer, sit on the left right to left, and
`TooltipLeft` opens on the start side. A code block stays left to right
in every locale. Contracts rule GOFASTR1824 refuses a physical side in
kit CSS, so a new component cannot drift back.

### The shell on client-side navigation

`WithLangFunc` tags every full-page render, but a client-side navigation
never re-renders `<html>`: it swaps layout layers inside `<body>`. After
an English page, a Spanish page reached by partial navigation kept
`lang="en"`, the English skip link, and the English header (#408).

The fix has two halves, and a multilingual site wants both:

1. **Key the outer layer per language.** Two layouts with the same name
   compare as the same layer, so the first one loaded stays on screen.
   Give each language's shell the same name (one CSS contract) and a
   per-language `WithKey`; a language switch then re-renders the shell
   like any other cross-chain navigation.

2. **Let the document markers travel.** The outermost layer of every
   render carries the page's resolved language, its direction and the
   skip label (`data-cui-lang` / `data-cui-dir` / `data-cui-skip-label`),
   and the runtime copies them onto `<html lang>`, `<html dir>` and the
   skip link after every swap. You get
   this by declaring the resolvers; there is nothing to render yourself.

<!-- gofastr:compile
import "context"
import "strings"
import "github.com/DonaldMurillo/gofastr/core-ui/app"
import "github.com/DonaldMurillo/gofastr/core-ui/html"
import "github.com/DonaldMurillo/gofastr/core/render"
type ReferenceScreen struct{}
func (r *ReferenceScreen) Render() render.HTML { return render.Text("Reference") }
func docsHeader(ctx context.Context) render.HTML { return render.Text("Docs") }
-->
```go
shell := func(key string) *app.Layout {
    return app.NewLayout("docs", app.LayoutSpec{},
        func(ctx context.Context, l *app.LayoutTree) render.HTML {
            return html.Div(html.DivConfig{},
                html.Header(html.HeaderConfig{Banner: true}, docsHeader(ctx)),
                l.Primary(),
            )
        }).WithKey(key)
}
application := app.NewApp("docs").
    WithLang("en").
    WithLangFunc(func(path string) string {
        if strings.HasPrefix(path, "/es/") {
            return "es"
        }
        return "" // fall back to Lang
    }).
    WithSkipLabelFunc(func(path string) string {
        if strings.HasPrefix(path, "/es/") {
            return "Saltar al contenido principal"
        }
        return "" // fall back to the English default
    })
application.Register("/en/reference", &ReferenceScreen{}, shell("docs-en"))
application.Register("/es/reference", &ReferenceScreen{}, shell("docs-es"))
```

`WithSkipLabel` / `WithSkipLabelFunc` localize the skip link, the first
string a keyboard user tabs to (#411); `SkipLabelFor(ctx, path)` resolves
like `LangFor` (func, then app-wide label, then the `app.skip_to_main`
phrase in the request's language, "Skip to main content" in English).
A page whose whole chain is shared with the previous one (same layout
instances top to bottom) swaps bare content and carries no markers, so
the document language cannot change on that hop. That is the contract
working as designed: if the language differs, key the outer layer per
language and the carrier always arrives.

### Host-built shells

The shells `uihost` builds itself — the 404, the 405, the embed frame — are not
app pages and resolve separately. A 404 under `/es/` that says `lang="en"` is
the same failure the pages had:

```go
host := uihost.New(application, uihost.WithLangFunc(esPrefix))
```

`UIHost.LangFor(ctx, path)` tries `uihost.WithLangFunc`, then the app's own
`LangFunc`, then the request's negotiated locale, then `EffectiveLang`. Because it falls through to the app, a site that declared
its languages once on the App gets its shells tagged without repeating itself.
A shell that belongs to no route, such as the PWA offline page, passes an empty
path and no request, and takes `EffectiveLang`.

Every fallback ends at `EffectiveLang`, so an app with no `WithI18n`, no
`LangFunc` and no `ScreenLang` gets the same `lang` as before, plus
`dir="ltr"`.

## Common mistakes

- **Don't forget the middleware.** Without it `r.Context()` has no
  Locale, every request falls back to the fallback locale, and
  per-user translations don't happen. `WithI18n` wires it
  automatically; if you opt out of defaults, you must mount it
  yourself.
- **Don't include user input in keys.** Keys are looked up verbatim.
  Passing user input opens up a "no such key returns the bare key"
  reflection vector. Always look up a fixed key and pass values as
  params.
- **Don't switch the default Translator at runtime.** `SetDefault`
  is for startup wiring; swapping it mid-flight is a race against
  any goroutine that's already cached `Default()`.
